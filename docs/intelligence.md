# Intelligence decisions and validation boundary

Research checked 18 October 2026. This release ships deterministic browser DSP and an evidence-driven curriculum engine. It ships no trained audio or vision models, ONNX runtime, WebGPU inference, generative coaching service or automatic hand-position diagnosis. Audio/video review remains useful without model downloads.

| Candidate | Useful next capability | Decision and cost |
| --- | --- | --- |
| ONNX Runtime Web | Run a validated audio model locally, using WebAssembly or supported GPU operators | Optional future worker integration. Benchmark model accuracy before adding runtime/download cost. The official runtime supports browser inference, but GPU operator coverage is narrower than WASM. [Runtime documentation](https://onnxruntime.ai/docs/tutorials/web/) |
| CREPE | Neural monophonic fundamental-frequency estimates | Compare against current YIN on real guitar recordings. It remains monophonic; it does not solve ringing chord transcription. No weights are included. [Author repository](https://github.com/marl/crepe) |
| Basic Pitch | Polyphonic note transcription and pitch bends | Candidate for offline analysis of ringing arpeggios. Its instrument-agnostic transcription capability is not proof of reliable beginner-guitar grading; verify onset, offset, missing-note and false-note errors. No model is included. [Spotify repository](https://github.com/spotify/basic-pitch) |
| MediaPipe Hand Landmarker | Handedness and 21 hand landmarks per detected hand | Optional camera overlay and framing check. The synchronous detection calls can block the UI; use a worker and cap frame rate. Landmarks alone cannot establish string contact, pressure or tension, especially with occluded fingers. [Google guide](https://developers.google.com/edge/mediapipe/solutions/vision/hand_landmarker/web_js) |
| WebGPU | Accelerate supported inference graphs | Feature-detect and retain CPU/manual fallbacks. Requires a secure context and compatible browser/device; support must not gate lessons. [Browser API documentation](https://developer.mozilla.org/en-US/docs/Web/API/WebGPU_API) |

No inference pricing estimate is meaningful without a selected model and deployment. Local inference removes per-request hosted inference charges, but still consumes device compute, battery, download bandwidth and hosting egress. For illustration, 10 million FP32 weights occupy about 40 MB before activations, runtime buffers, duplicated downloads or GPU transfers; FP16 weights occupy about 20 MB. These are arithmetic storage examples, not measured sizes of the candidates above. Record actual compressed download, peak RAM/VRAM, initialization time and sustained inference latency on representative phones. Browser/WASM allocation limits and model caching require explicit handling. [ONNX model memory guidance](https://onnxruntime.ai/docs/tutorials/web/large-models.html)

Acceptance requires player-disjoint annotated guitar takes: clean electric and acoustic, interfaces and phone microphones, quiet and noisy rooms, clipped and distorted signals, separated notes, ringing arpeggios, missing/extra notes and varied skill levels. Measure pitch/note accuracy, onset error, sequence errors, abstention quality, false mastery advancement and device resource use. [GuitarSet](https://github.com/marl/GuitarSet) is a research dataset candidate; verify its data terms and coverage before ingestion. It does not replace recordings from RIFF's intended beginner/device population.

Existing automated checks use generated harmonic/noise signals and a mocked AudioWorklet contract. The downloadable First Light reference is also synthesized. **No real-guitar validation corpus has been run, and no real-world accuracy claim is made.** Keep score/confidence labels tied to observed evidence; never upgrade mastery from an unscored ringing review or infer biomechanics from audio.

# Audio measurement

Microphone audio stays in the browser. HTTPS (or localhost) and explicit browser permission are required. The AudioWorklet receives mono PCM, posts timestamped 4096-sample blocks and outputs silence. It never monitors microphone sound through the speakers. Use headphones so metronome clicks and reference tones do not enter the microphone. Browser echo cancellation, noise suppression and automatic gain control are requested off; hardware and browser behavior may still vary.

`AudioEngine.prepareMicrophone(onFrame?)` creates the input once. `onFrame(samples, sampleRate)` receives live blocks for a tuner/waveform, including before recording. `startCapture()` returns the start time in AudioContext seconds. `stopCapture()` flushes the partial worklet block and resolves `{samples, sampleRate, startedAt}`. `close()` releases the microphone and audio context. `playTone(midi, duration?)` and `playExercise(exercise, bpm)` use a triangle oscillator with a short attack and exponential decay; these are synthesized pitch references, not recorded guitar technique demonstrations. `stopPlayback()` stops scheduled voices. `startMetronome(bpm, beatsPerBar=6)` resolves the first scheduled tick time; `stopMetronome()` cancels its scheduler. Tempo counts one exercise beat per `60 / bpm` seconds; for the six-pulse exercises this is the eighth-note pulse.

For a recorded count-in, start capture, then start the metronome. Slice `(firstTick - startedAt + countInPulses * 60 / bpm) * sampleRate` samples before evaluating. The audio clock determines the boundary; JavaScript countdown rendering is decorative. Avoid audible references while evaluating. Metronome ticks use a 25 ms scheduler with 100 ms audio lookahead. Background-tab throttling can disrupt scheduling.

`detectPitch` uses the YIN cumulative normalized difference function, box-averaged decimation and parabolic lag interpolation. Supported fundamental range is approximately 65–1400 Hz. `extractNotes` uses 10 ms envelope hops, 75 ms pitch windows, rising-energy attacks and stable pitch changes. It targets clean, separated, monophonic guitar playing. Polyphonic chords, heavy distortion, sympathetic ringing, very fast passages and legato need more advanced analysis. Estimated pitches are quantized to MIDI semitones: this release assesses note choice, not precise intonation or bends. Onset resolution and pitch windowing introduce measurement error.

`analyzeRecording(samples, sampleRate, exercise, bpm, latencyMs=0, mode='separated')` aligns note sequences with insertion/deletion/substitution costs. Missing and extra attacks remain explicit; the sequence is not truncated to the shorter performance. `weakestTransition` identifies the destination note index, starting at 1. Absolute attack errors are retained: no best-fit offset conceals late playing. Without explicit latency compensation the timing includes capture/hardware latency. Timing is a useful practice signal, not a laboratory measurement. `mode='ringing'` always returns null scores and a listening-review explanation. The practice room offers this mode for arpeggios, transitions and the complete study. For scored takes, release each note before the next. Automatic detection of all polyphony is not claimed: harmonically related overlapping strings can fool monophonic pitch confidence.

Silence, nonfinite PCM, clipping above 0.5% of samples and failure to isolate periodic notes return low confidence with null scores. Confidence describes signal suitability, not a calibrated probability that the interpretation is correct. Clean periodic non-guitar sounds can still be detected; this is not an instrument classifier. Sparse successful detections must be interpreted alongside the missing-note count.

`compareMuting(open, muted, sampleRate)` measures each attack's time to a 12 dB amplitude decay and compares mean decay and variation. Notes interrupted by the next attack before reaching the threshold are excluded. Keep gain, distance, effects and picking strength comparable. Results are relative acoustic observations with at most medium confidence; they cannot establish palm placement, tension or biomechanical causes. No result is emitted when either recording is silent, clipped, invalid or lacks measurable decay.

Run `npm test` for synthetic harmonic pitch, noise/silence/clipping, repeated attacks, missing/extra sequence alignment, latency and relative decay checks. Real-guitar microphone/device benchmarking remains necessary before claiming accuracy across instruments and environments.

References: [YIN paper, de Cheveigné and Kawahara (2002)](https://doi.org/10.1121/1.1458024), [AudioWorklet processing contract](https://developer.mozilla.org/en-US/docs/Web/API/AudioWorkletProcessor/process). The implementation reads actual render-block lengths instead of assuming that every browser render block is 128 samples.
